## 2026-10-21 1 回目（main 6cdcc4f）

### ユーザーの報告

1. 一部の Gmail アカウント（契約切れ）で「Failed to fetch」が表示される。
2. Gmail に `/u/3/` のアカウントがあるのに、一覧に出ない。
3. 未読は検出されるが、Gmail でメールを削除しても一覧に未読が残ったまま。少し待つと更新された。

### 分析

| # | 判定 | 原因 | 対応 |
|---|---|---|---|
| 1 | 不具合（表示の不親切さ） | 契約切れのアカウントのフィードは、権限のない URL に転送されるなどで fetch が TypeError（"Failed to fetch"）になる。アカウント自体は使えないので error 表示は正しいが、メッセージから原因が分からない | TypeError のときは原因の候補を補ったメッセージにする（`src/providers/gmail.ts`） |
| 2 | 不具合 | `discoverGmailAccounts` が error で検出を打ち切っていた。`/u/2/` が error になると `/u/3/` 以降を取得しない | error では打ち切らず次の番号に進む。error が 2 件連続したら Gmail 全体に到達できないとみなして打ち切る（設計 §6.2 を更新） |
| 3 | 仕様どおり | 一覧はチェック結果の保存値で、ポップアップを開いた時点で再チェックする。Gmail 側の既読・削除がフィードに反映されるまで時間差がある | README の「制約と注意」に記載。コードは変更しない |

### 回帰テスト

- `tests/gmail.test.ts`
  - 途中のアカウントが error でも打ち切らず、error として加えて次のアカウントを検出する（Issue #30）
  - 500 のアカウントは error として加え、次のアカウントの検出を続ける
  - error が連続したら打ち切り、それまでの結果は残す
  - ok を挟めば error の連続回数は数え直す
  - fetch が TypeError で失敗したら、原因の候補を補ったメッセージで error

修正前のコードで上記のテストが失敗し、修正後に全テスト（26 ファイル / 330 件）が成功することを確認した。
